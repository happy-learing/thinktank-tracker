# 智库研究追踪

面向 Windows 10/11 x64 的本地 Web 应用。程序解析 Word 中的智库清单，采集研究栏目，将指定日期范围内的全部正式内容完整展示，再执行确定性日期/体裁/篇幅筛选，调用 DeepSeek 或其他 OpenAI 兼容模型进行主题判断，并在人工复核后导出 Word 报告和 Excel 审计表。

详情页发布日期按 JSON-LD、发布元数据和主记录日期字段的证据优先级确定，相关推荐日期不会覆盖主日期。体裁只接受两类确定性证据：URL 的完整独立路径段，以及栏目卡片 DOM 中的完整标签文本；CSS 隐藏或悬停显示的标签仍会读取。内置规则将单复数和站点别名规范化为统一体裁，URL 与标签冲突、未知标签或均未命中时一律转人工，不做模糊子串猜测。设置页可配置“匹配方式、匹配值、规范体裁、处理方式”，来源高级设置可为新智库填写卡片容器和体裁标签 CSS 选择器。

来源按独立“检索配置”管理。每个配置保存自己完整的智库、入口、适配器、排序方式和发现规则；同一官网可以分别存在于多个配置，修改其中一个不会影响其他配置。可新建空配置或深度复制当前配置，复制后的链接测试状态统一为“未测试”。新建任务必须明确选择配置，任务创建时会保存配置、智库和入口规则快照，之后修改配置不会改变旧任务或其断点恢复。

一个智库可以配置多个检索入口。程序只从用户给定入口及其分页发现文章，不从详情页的相关文章继续扩散；详情页可以位于同站其他合法路径。新建入口默认使用 `auto`，由入口 URL 解析 ECFR、EUISS、CEPS、Martens Centre、Egmont、EPC 和 Elcano 等内置适配器，未知网站才回退到通用适配器；用户明确选择 `generic` 时保持该选择。ECFR 分页只接受 `/analysis/page/N/`，不会采用跳出栏目的 `/page/N/`。来源页的“测试链接”会测试当前智库的全部启用入口，显示实际适配器、采集引擎、卡片数、合格文章数、拒绝原因、当前/下一页和样例；HTTP 页面未识别到卡片时会用 Chromium 渲染同一首个栏目页再检查，不创建任务、不生成候选，也不调用模型。

日期范围内的新闻、评论、活动、短文和主题不符内容也会保留并显示排除原因；日期不明项单独警告，边界扫描遇到的范围外内容默认折叠。按日期排序的入口越过起始日后只再验证 10 条新发现、日期已确认的过旧正式内容；日期不明、置顶重复或顺序逆转不会计入这 10 条。

作者按 JSON-LD、标准作者元标签、适配器详情选择器、栏目卡片选择器的顺序提取；程序不让模型生成作者。人工复核页可按“每行一位作者”修订。批准纳入必须同时具有已确认日期、唯一主分类、英文标题、中文标题、体裁、核心观点和至少一位作者。

主题判断只在日期、体裁、篇幅和正文提取通过后调用一次模型。输入由标题、官网摘要、标签、正文标题、开头、结论和尾部组成，默认正文上限 20,000 字符。模型必须给出主题决定、唯一主分类、战略关联、理由、最多三条可逐字回查的证据和置信度；纳入阈值为 0.75，排除阈值为 0.85，其余或证据回查失败均转人工。模型结论只是建议，只有人工批准项进入 Word。

正式 Word 使用内置参考模板，文件名为 `YYYY年M月D日-YYYY年M月D日.docx`，按任务创建时的智库顺序分组，条目格式为“作者, 英文标题（中文标题）, 英文完整日期”，URL 独立成段并可点击。无符合项、覆盖不完整、体裁、核心观点及其他审计信息只保留在 XLSX。任何已批准条目缺少作者、双语标题或确认日期时，整次 Word 导出失败并列出候选编号。内置 `report_template.docx` 是供程序填充的空白样式资源，直接打开看见空白属于正常现象；发布包中的 `示例文件/智库周览格式示例.docx` 才是供用户查看的完整格式示例。

详情页存在 PDF 时，无论 HTML 正文长短都会执行附件发现。程序区分主文件、补充材料和页脚文件，校验 PDF 文件头，记录下载状态与原始文件 SHA-256，并优先使用更完整的主 PDF 作为正文。PDF 默认由本地 AnyDoc 0.2.4 转成 Markdown，明确拒绝托管 OCR；结构转换失败或正文过短时回退 pypdf，密码保护和资源上限拒绝不会回退。设置页可一键切换为仅 pypdf。来源入口和已结束任务使用回收站删除，可恢复；永久清除前会自动备份数据库。

## 开发运行

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-build-isolation -e .
.\.venv\Scripts\thinktank-tracker.exe
```

运行数据只写入项目或便携包旁边的 `workspace/`。另一台电脑使用时复制完整发布目录并重新录入 API 密钥；两台电脑的数据互不合并。数据库升级到 schema v10 前会在 `workspace/backups/` 自动生成迁移前备份；v10 会在严格保护自定义配置的条件下修复 ECFR 适配器，并从历史证据恢复被清空的原始体裁标签，不联网重抓，也不改动已审核或已批准结果。`sources.json` schema v6 可导出当前配置或全部配置，并兼容导入旧格式；Word 和旧版 JSON 导入当前选中的配置。程序已经运行时再次双击 EXE，会复用原服务并重新打开一个浏览器标签页。

## 发布目录

```text
ThinkTankTracker/
  启动智库追踪.exe
  app/                 # PyInstaller 运行时与依赖
  runtime/browsers/    # 与 Playwright 版本匹配的完整 Chromium 及辅助组件
  示例文件/           # 可直接查看的智库周览格式示例.docx
  workspace/           # 数据库、配置、缓存、日志、导出、备份
  VERSION
  SHA256SUMS.txt
```

构建前运行 `scripts/install-browser.ps1`，再运行 `scripts/build-portable.ps1`。发布包携带程序实际使用的完整 Chromium 和辅助组件，以支持普通浏览器渲染及反自动化页面回退。构建产物为 `onedir` 目录及完整 ZIP，不要求目标电脑安装 Python、Node、数据库或浏览器组件。

## 强制发布规则

项目的任何更改，包括源代码、配置、模板、构建脚本和 Markdown/文本说明文档修改，都必须提升版本并生成一个新的完整发布包，不允许只提交修改而不打包。若当前版本已经存在发布目录或 ZIP，必须先提升 `VERSION`（至少增加补丁版本），并同步更新程序元数据后再构建；禁止覆盖、删除或复用既有版本的发布产物。此规则适用于本次及以后每一次更改。

每次发布必须依次完成完整测试、`scripts/build-portable.ps1` 构建、包内 `验证完整性.ps1` 校验和 `scripts/smoke-portable.ps1` 冷启动验证。最终交付必须明确给出 `release/ThinkTankTracker-win-x64-portable-full-vX.Y.Z.zip` 的路径、文件大小和 SHA-256。构建脚本会在发现同版本发布目录或 ZIP 时直接终止，以强制保留历史版本。
