# 智库研究追踪

面向 Windows 10/11 x64 的本地应用。导入 Word 智库清单，选择独立检索配置及日期闭区间，采集文章和主 PDF，分析国际战略研究内容，输出自动 Word 草稿、人工批准报告和 Excel 审计表。

v0.7.1 将文章事实、研究价值、报告就绪状态分开。网页发布日期缺失、官方体裁未知时，只要正文完整，仍可分析研究价值；报告纳入则单独检查任务门槛、作者和双语标题。默认采用严格模式：英文至少 1500 词、中文至少 3000 字、体裁必须满足允许规则；设置页也可明确选择实质分析优先模式。新任务保存筛选规则快照，修改设置不改变旧任务；手动点击重算只更新指定任务的体裁规则，保护人工处理记录。

官方体裁以文章标签、栏目卡片和 URL 独立路径段为证据。标签先完整匹配，再作有英文单词边界的词组匹配，例如 Policy Brief No. 42；report 不匹配 reportage。不在全文、相关推荐或任意 URL 子串里寻找 report 就认定体裁。多个相矛盾的命中保留冲突，原始标签及命中来源可回查。

模型判断实质分析及国际战略关联：研究问题、论证或机制解释、核心结论必须能从文章找到依据，偶然提及中国、美国、科技、能源不构成纳入理由。短文整篇输入；长文按连续段落覆盖、综合判断后再进行质疑式复核。引用同时校验实际输入与保存的原文；缺段、预算耗尽、格式错误、复核冲突均保留待处理状态。模型自报分数仅存档，不是准确率，也不再以 0.75/0.85 自动决定去留。默认每篇最多 12 段，可设置 1 至 30 段；短文通常 2 次逻辑调用，长文通常段数加 2 次，格式修复和接口兼容回退可能增加请求。

自动草稿收录通过程序核验和模型复核、事实字段完整的条目，以及人工批准条目。草稿明确标识自动性质、来源覆盖及待处理清单，不伪造人工批准。正式报告仍仅包含人工批准项，保持原有模板。自动草稿不代表零误判；同一模型的分析与复核可能有共同偏差，需要结合实际标注样本抽查。候选页可重新分析已保存正文，不需重新下载；人工决定不会被覆盖。

采集按需要升级：HTTP 取得有效正文时直接使用；HTML 返回 403 或验证页时使用 Scrapling 0.4.15 StealthyFetcher 和包内 Chromium 恢复。动态空栏目先普通浏览器，失败后再 Scrapling。测试链接与正式采集共用卡片发现与恢复路径；渲染后仍为空、错误页或验证页不能报成功。保留实际 HTTP 状态和尝试记录。此机制无法保证所有站点和所有时间均可访问。

PDF 默认继续使用本地 AnyDoc 0.2.4，结构转换失败或过短时回退 pypdf；不自动启动托管 OCR。识别 View PDF、Read PDF、全文下载和文档类型词组，补充材料不会替代主文档。主 PDF 未成功提取且 HTML 疑似摘要时标记 partial，防止按摘要词数排除研究。PDF 替换正文时保留官方页面标题、作者、日期和体裁证据。Egmont 文章标题区的明确署名优先于 JSON-LD 中的 CMS 机构账号。

来源按独立配置管理，每个来源可有多个入口，保存配置、入口和规则快照。仅从用户选定入口及分页发现内容，不从详情相关推荐扩散。ECFR 专题 /special/ 链接也接受为候选，仍须后续判断研究价值；ECFR 分页限制在 /analysis/page/N/。分页循环、安全页数上限、无候选及恢复失败会标记覆盖问题。任务在发现结束但仍有待处理内容时显示完成但有问题。

人工批准需有已确认且在任务日期范围内的日期、主分类、双语标题、作者及核心观点；严格模式另检查体裁。不能为了批准而改写真实日期或体裁。Word 保留任务中的智库顺序、英文完整日期和可点击原文链接；Excel 保存过程证据。运行数据只写入 workspace，密钥保存在 Windows 凭据管理器，另一台电脑需重新录入。数据库 schema v11 升级前自动备份；升级本身不重抓、不修改历史审核结果。

## 开发运行

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-build-isolation -e .
.\.venv\Scripts\thinktank-tracker.exe
```

旧版数据可随 workspace 迁移，启动时自动备份并升级数据库。历史自动判断没有新流程的全文覆盖与复核证据时，不能直接进入新草稿；可在候选页重新分析。人工已批准结果继续受保护。

## 发布目录

```text
ThinkTankTracker/
  启动智库追踪.exe
  app/                 # PyInstaller 运行时与依赖
  runtime/browsers/    # 与 Playwright 版本匹配的完整 Chromium 及辅助组件
  示例文件/           # 可直接查看的智库周览格式示例.docx
  workspace/           # 数据库、配置、缓存、日志、导出、备份
  VERSION
  SHA256SUMS.txt
```

构建前运行 `scripts/install-browser.ps1`，再运行 `scripts/build-portable.ps1`。发布包携带程序实际使用的完整 Chromium 和辅助组件，以支持普通浏览器渲染及反自动化页面回退。构建产物为 `onedir` 目录及完整 ZIP，不要求目标电脑安装 Python、Node、数据库或浏览器组件。

## 强制发布规则

项目的任何更改，包括源代码、配置、模板、构建脚本和 Markdown/文本说明文档修改，都必须提升版本并生成一个新的完整发布包，不允许只提交修改而不打包。若当前版本已经存在发布目录或 ZIP，必须先提升 `VERSION`（至少增加补丁版本），并同步更新程序元数据后再构建；禁止覆盖、删除或复用既有版本的发布产物。此规则适用于本次及以后每一次更改。

每次发布必须依次完成完整测试、`scripts/build-portable.ps1` 构建、包内 `验证完整性.ps1` 校验和 `scripts/smoke-portable.ps1` 冷启动验证。最终交付必须明确给出 `release/ThinkTankTracker-win-x64-portable-full-vX.Y.Z.zip` 的路径、文件大小和 SHA-256。构建脚本会在发现同版本发布目录或 ZIP 时直接终止，以强制保留历史版本。
