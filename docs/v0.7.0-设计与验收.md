# v0.7.1 结果导向重构

目标：在用户选定的来源、入口、日期和纳入门槛内，找到有实质分析的国际战略研究，保留证据并整理报告，减少重复人工判断。版本号不是可靠性证明，能重现的测试结果才是证据。

## 从结果推导责任

1. 来源覆盖回答“是否发现了应看的候选”。403、动态空列表、错误入口、路径白名单漏项和分页中断属于采集问题，不应解释为没有符合文章。
2. 正文获取回答“是否读到了要判断的材料”。网页摘要有主 PDF 时先取得主 PDF；主文档失败不能用摘要字数否定研究。
3. 客观事实回答“何时发表、作者是谁、网站如何标注、正文多长”。官方标签、日期与署名保存来源；模型不能生成这些事实冒充官网证据。
4. 内容分析回答“国际战略是否是主论题，是否有研究问题、论证和结论”。标签和长度不能替代这一判断。
5. 报告就绪回答“本次规则和必要字段是否满足”。一个研究可以有价值但尚缺日期，应该保留分析并提示缺什么。

严格模式默认保留字数和体裁硬门槛。另提供明确选择的实质分析优先模式，不擅自把用户的硬条件降为提示。每个新任务保存规则快照，重新归类只在用户明确发起的任务内执行。原始事实、模型决定和人工决定分别保存。

## 组件取舍

| 职责 | 实际采用 | 取舍 |
|---|---|---|
| 普通公开网页 | HTTPX | 当前多数来源能直接取得页面，保留低开销路径 |
| 403及验证页恢复 | Scrapling 0.4.15 StealthyFetcher | 前期对照及本次 ECFR 实测支持定点引入；携带原生依赖和完整 Chromium |
| 普通动态空列表 | Playwright，失败再 Scrapling | 所有入口测试与正式扫描使用同一恢复逻辑 |
| PDF转Markdown | AnyDoc 0.2.4 | 用户实际反馈及主 PDF 实测支持保留；结构失败才回退 pypdf |
| 任务、事实、人工结果 | SQLite、SQLAlchemy | 无需增加服务部署，保持 Windows 单机便携 |
| 报告与审计 | python-docx、openpyxl | 复用既有可检查模板，新增草稿与核验页 |

未加入 Crawlee、Docling、PyMuPDF4LLM：本轮没有证据证明为当前流程同时引入它们的收益大于依赖和迁移成本。用户授权全部可以改，不等于每个组件都必须换。

上游来源：[Scrapling](https://github.com/D4Vinci/Scrapling)、[AnyDoc](https://github.com/firecrawl/anydoc)。版本锁定是可重复构建选择，不代表上游永远没有更新。

## 降低人工负担的方法及其边界

短文完整输入；长文按连续区间分段分析，所有段落记录可回溯，再综合主论题。引文必须存在于本次实际输入和原始正文，伪造引文、越过分段预算、格式错误不能通过。模型结论再进入质疑式复核，主动核查偶然战略提及、宣传性文字、错误核心结论和错误排除。self confidence 仅为自评分，不当作准确率。

同一模型复核可能重复初次错误，逐字引文也不证明推理一定正确，因此自动通过仅进入明确标记的草稿。人工优先处理异常，再对自动纳入和排除进行抽查。未实现经验校准的自动放行阈值，也未声称达到任何准确率或减少人工百分比。需要真实人工标注语料，分别测量误收率、漏收率和人工处理率后才能回答。

目前复核使用用户配置的同一个模型；没有多模型独立性保证。短文通常两次逻辑调用，长文通常段数加两次；接口格式兼容回退和修复可能增加实际请求。大幅长文覆盖提高了完整性，也增加成本，预算可配置。

## 已复现并修复的故障

- HTTP 403 直接异常导致回退不可达：现在进入 Scrapling 并检查恢复后的真实状态和页面内容。
- 测试入口能恢复而正式扫描不能：共用 listing_cards 与 render_resource。
- ECFR 栏目中的 /special/ 被路径规则丢弃：接受为待分析候选，仍按内容判断。
- Egmont View PDF 未被认作主文档：新增按钮语义和文件名词组规范化。
- Egmont JSON-LD 用 CMS 机构账号冒充研究作者：限定在文章标题区的可见署名优先。
- EPC 广泛 author 选择器吸收推荐文章作者：优先使用当前文章作者区域，并回归测试推荐作者不混入。
- 体裁未知时不分析正文：现在与研究分析分开，报告仍检查任务规则。
- 只看长文头尾及自评分阈值：改为连续覆盖、引文回查与质疑复核。
- 手动批准提示要求改变真实日期或体裁：改为说明范围冲突，不鼓励修改事实。
- 历史模型结论重分类后绕过证据门禁：没有新核验证据不会直接进入草稿。

## 当前验证证据

2026年9月10日，实际生产抓取路径访问 ECFR、EPC、CEPS、EUISS、Egmont 的入口均识别到卡片。ECFR 恢复后 HTTP 200，10 张卡片；EPC 10；CEPS 正确入口 /ceps-publications/ 为18；EUISS10；Egmont6。错误 CEPS /publications/ 返回404，已明确保留为错误入口，不能算抓取成功。

Egmont《A Periphery Without a Core》：修复前选用了176词网页摘要，修复后 AnyDoc 主 PDF 输出4052词，识别 policy brief 和 Sven Biscop、Bernard Siman 两位作者。此案例直接说明主文档选择和字段来源规则比盲目替换转换器更关键。

这些是有限时点、有限页面验证，不是全站覆盖或长期稳定性证明。开发沙箱不能读取当前用户的模型密钥；随后在当前用户会话用已配置的 deepseek-v4-flash 对两篇公开文章完成真实 API 冒烟验证，复现了复核输出证据条数过多的格式失败，v0.7.1 加入一次格式修复。它们不是准确率统计样本，自动结果仍需抽查。

完整测试、版本包构建、校验和、原生 AnyDoc 与 Scrapling 回环浏览器冷启动检查，按 README 的发布流程执行。最终实际结果单独记录于 artifacts/qa-v0.7.0。
